# Working on VELOCITY

1. Check Git status, the [progress record](docs/progress.md) and the [roadmap](docs/roadmap.md). Work only on the human-authorized phase. Preserve existing work.
2. For changes to controls, scenes or motion, consult the [design system](docs/design-system.md), [architecture](docs/architecture.md) and [animation guidelines](docs/animation.md). Introduce a dependency only when the current deliverable needs it.
3. Before importing or distributing an asset, complete its [license record](docs/asset-licenses.md).
4. Run the phase's [verification gates](docs/testing.md). Record results, independent review findings, fixes and human acceptance in progress. A failed or pending gate keeps the phase open. Begin the next phase only with human authorization.
5. The human controls Git publication. Keep work local unless the human explicitly authorizes the specific commit, push, merge or deployment. Check for automatic deployments before publishing a branch.

## Obsidian Programming Brain

When prior project knowledge would help, start with `~/Developer-Brain/00-Start-Here.md`. Read only task-relevant notes. Reuse applicable lessons after verifying them against current source. Explain important programming concepts in beginner-friendly language. End development sessions with a short proposed learning summary. Ask for approval before editing any vault note. Never store passwords, API keys or secrets in the vault.
